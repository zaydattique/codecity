# Architecture | foundation v0.1

## Runtime boundary

Godot owns world transforms, collision, physics, animation, navigation, inventory, transactions, mission state and the authoritative clock. Python chooses bounded intents, never writes a scene or teleports an NPC. No network service, LLM or paid API required. Renderer selection is provisional: GL Compatibility for boot and low-spec experiments; benchmark Forward+ and Mobile on target GPUs before choosing art/shader requirements. Fixed 60 Hz physics initially; do not change tick rate merely to accommodate a reference vehicle. World clock uses integer ticks, 120 ticks/game minute (2 seconds at 60Hz), 08:00 start; pause with tree. Clock restore rejects invalid values. Day length and time scale require gameplay approval.

Scene ownership: root Bootstrap transitions from dev foundation to a future World root; World owns ChunkManager, Actors, Vehicles, Environment and MissionDirector. Actors are composed of movement, animation, perception, interaction and intent consumer. Player and NPC feed the same movement interfaces through separate input sources. Player camera uses spring arm and occlusion checks; vehicle entry is a transactional reservation, animation, control transfer, rollback. NavigationAgent3D is for local pedestrian paths; directed lanes with conflict-zone reservations handle traffic. Avoidance only where needed; never globally query all actor pairs. Godot EventBus emits committed facts after state updates, not commands. Listener errors cannot silently authorize actions. Stable event and asset IDs survive scene unloads. No singleton for every actor.

## Input and world interfaces

Input map: WASD move, Shift sprint, C crouch, Space jump/vehicle brake, E interact, P phone, Escape pause. Context router is required before gameplay to prevent cross-mode input, controller mapping and focus restoration. Only registered action names exist now; no movement code. Interactions use actor/target IDs, range, LOS, availability, reservation token, commit after animation marker and idempotent cancellation. All state consumers validate target existence and permissions.

World scale: metres, +Y up, Godot forward -Z; Blender Z up with canonical front -Y, validate conversion with axis/scale fixture. Spatial IDs `district.chunk_x_z.entity`, asset IDs `category.name.vNNN`, immutable IDs independent of display text. Proposed chunks 64 m with 2-ring prefetch initially; actual street designed by geometry, not grid repetition. Chunk lifecycle unloaded/requested/loading/active/retiring; prefetch along velocity, hysteresis and collision/nav readiness before activation. Keep pinned mission/occupied chunks; serialize NPC abstract state before despawn. Threaded loading with main-thread scene attachment under time budget. No world streaming yet.

## Python NPC architecture (planned P23)

Each agent has seeded identity, personality traits, needs, occupation, schedule, relationship map, recent bounded events and persistent memory of significant encounters. Godot supplies timestamped observations derived from proximity grid, hearing radii, LOS and activity context, not omniscient coordinates. Python utility scores eligible goals (work, rest, shop, socialize, shelter, avoid danger) with needs, traits, memory, schedule, cooldown and deterministic tie-break. Short finite-state action plans and reservations prevent conflicting goals. Use hysteresis and minimum commitment time to avoid thrashing. Some NPCs ignore a bump, others step away or complain based on personality and history. Recognition decays with time; persistent memory capped per actor, save only meaningful encounters. NPC-to-NPC activities and work should proceed without player. No visible decision trees or internal emotion bars. Simulation uses seed plus per-agent ID, deterministic iteration order and versioned configuration. A path failure returns a fact and triggers bounded replan/backoff. Do not fabricate outcome from an intent.

## Local IPC v1

Implemented: Python stdin/stdout JSON Lines probe only, exact request `{ "version":1,"id":"boot.1","op":"ping" }`; responds pong with capabilities `["ping"]`. UTF-8, 64 KiB frame including newline, duplicate keys and nonfinite constants rejected, unknown ops fail, oversized/unterminated frame closes with code 2. No network socket, shell evaluation or filesystem request. Logs stderr only; stdout reserved for protocol.

Planned decide envelope: version, request ID, generation, simulation tick, seed and up to 32 observation records; each record has agent_id, need/schedule/trait snapshots, max 16 perceived events with validated IDs and finite numerics. Response includes same correlation fields and up to one intent per input actor: enum action, allowed target ID, expiry tick, reason code development-only. Define exact JSON schemas and shared fixtures before implementing decide. Godot sends one in-flight batch per worker on background I/O, 50 ms soft deadline and 200 ms hard deadline initial; abandon stale IDs/generations, reject unknown IDs, ranges, nonfinite values and unavailable actions. No blocking physics. Start child with fixed packaged path and no shell; handshake, monitor exit, close pipes, kill/join on shutdown, exponential restart backoff capped at 30s. Validate response length before parsing. On timeout maintain safe existing action if still valid, otherwise stop safely/yield or follow cached routine; tag fallback in development logs and never present it as Python execution. No Godot bridge or timeout supervisor implemented now. Worker packaging evaluated on Windows; do not ship Blender or dev venv.

## Revised dual-mode architecture

The master directive supersedes single-mode scope. Session selection uses stable mode IDs living_world and academy, and character IDs adrian and maya. `game/core/session_state.gd` provides bounded in-memory profiles, activation only with a spawned Node3D and isolated completed-mission lists; no disk storage yet. `game/core/world_interaction.gd` supplies shared range/tree preconditions, not complete LOS/reservation or domain handlers. Profile persistence will be versioned with separate per-mode world snapshots (money, inventory, vehicles, last location, progress), shared settings and atomic backup. Continue must resolve the actual last mode/slot. No fake scene transitions. `ai/academy_contract.py` is a trusted broker-result validator, not a sandbox or Python interpreter. See Academy curriculum for fail-closed sandbox gate; NPC worker remains trusted and separate. Master directive is authoritative for input and final slice requirements.

`game/core/scene_loader.gd` implements a one-in-flight allowlisted threaded PackedScene loader; progress comes from ResourceLoader and scene result is consumed once. No world scene approved or connected to UI yet. Engine fixture loads the real boot scene as a test, not simulated gameplay. Mode/profile selection must resolve a real spawn and approved scene before activation.

The development boot scene now supports a validated temporary local profile and real mode/character selection via SessionState.select_draft. Draft selection is distinct from active spawned session; selection cannot start nonexistent scenes or write fake progress. Actual loading resource contract remains separate. Persistence and playable world launch remain later gates.

Candidate world uses one HarborLayout coordinate authority for collider footprint and map. StreetPlayer owns physics and collision-aware camera, menu activates session only after loaded candidate actor spawns. Minimap/full map use same coordinates, waypoint restricted to street; no route graph, fake POIs or non-existent city. Mode/profile state remains separate, Academy launch disabled until actual mission runtime exists.

P09 development VehicleBody3D owns driving physics and controls; actual wheel nodes are reparented to the four measured suspension raycasts, separate rear traction and front steering. Harbor scene mediates entry/exit via shared range, line of sight, speed/contact and safe capsule ground query; switches player collision/input and map actor. Pause and map disable occupied-actor controls. Candidate only, no high-fidelity tyre model or seated animation yet.

Academy pilot is a Python-authored bounded interpreter for a subset of real Python syntax, not native arbitrary code execution. Python AST parser plus explicit evaluator controls fictional lamp state; only bounded validated data commands can reach Godot. Godot remains renderer/physics/UI and authoritative actual light state. Local trusted process bridge uses unique request/reply file paths, 5s timeout and atomic result; no shell. No WASM sandbox yet; this restricted teaching interpreter is a distinct limited alternative, not unrestricted execution. University requirement: project is mixed Python/GDScript, Python is substantive educational computation; do not claim all engine code is Python.
