CODECITY: LIVING WORLD
MASTER PRODUCTION PROMPT PACK | English instructions for coding and art agents

USAGE
Place this file and CodeCity_Project_Instructions.txt in the repository or provide them to the agent. Start with P00, then P01 and the vertical slice. Each numbered prompt is an independent assignment; prepend the common quality contract below. Commands are proposed interfaces to implement, not existing scripts. Use a pinned Blender and Godot executable on Windows. Do not claim a model is built unless its binary file, preview and in-engine checks exist.

COMMON QUALITY CONTRACT (prepend to every assignment)
Act as a senior game developer, AAA technical artist and QA engineer. Produce original, editable, production-ready game assets, not screenshots or flat illustrations pretending to be 3D. GTA V is a visual aspiration, not a claim or permission to copy. Use licensed professional base meshes, phototextures and motion capture. Never make human characters out of primitive geometry. Use realistic proportions, topology, UVs, PBR materials, normal/roughness/metallic maps as appropriate, metric scale and consistent coordinate conventions. Apply transforms, inspect normals, avoid z-fighting, clipping, broken rigs and missing textures. Author LODs, simple collision proxies, interaction sockets and sensible texture budgets. Deliver .blend source, game-ready .glb, import settings, preview renders and license/validation records. Test in actual Godot scenes under daylight, indoor and night lighting. Do not accept generic low-quality placeholders as final. If tooling or licensed source is unavailable, report that precisely. Use one coherent realistic art direction. Reuse shared pipelines and materials rather than duplicating code.

P00 | FOUNDATION AND ARCHITECTURE
Read repository rules and inspect the current tree. Pin stable Godot/Blender/Python versions and create a minimal runnable game scene. Define scene ownership, event bus, simulation clock, input map, save schema, asset IDs, streaming and IPC interfaces. Keep game/ for Godot, ai/ for Python, tools/ for asset builds, tests/ and docs/. Add .gitignore, selective LFS policy and third-party notices. Establish headless import and test commands. Create roadmap with phase goals, acceptance gates and documented dependencies. Run a smoke test and report real results.

P01 | OPEN-SOURCE RESEARCH AND REUSE
Inspect exact upstream commits, README, LICENSE and per-asset notices. Candidate references (web listings checked, not downloaded or tested):
https://github.com/webgl-games/opencity - MIT code according to project listing; inspect Godot compatibility and separate asset licenses; use on-foot/vehicle transitions, traffic and procedural city only where appropriate. Do not keep prototype art as final.
https://github.com/gdquest-demos/godot-4-3d-third-person-controller - MIT code; demo art has separate terms; verify exact asset license and attribution before importing. Use movement, camera and animation architecture.
https://github.com/godotengine/godot-demo-projects - MIT demo code; choose branch matching pinned engine; inspect 3d/truck_town, navigation and physics examples.
https://github.com/ogeeice/Vehicle - CC0-listed vehicle example; evaluate handling before reuse.
https://github.com/makehumancommunity/mpfb2 - Blender character pipeline, GPL tool code and separately licensed graphical output; verify all clothing/hair add-ons individually.
https://static.makehumancommunity.org/mpfb/docs.html - installation and export guidance.
https://polyhaven.com/ and https://ambientcg.com/ - candidate PBR textures, HDRIs and props; confirm asset-level licenses.
https://www.mixamo.com/ - candidate animation source; confirm current terms and permitted redistribution before packaging. Do not bypass login or automate prohibited downloads.
Search for additional compatible permissively licensed navigation, traffic, vehicle physics, modular city and humanoid animation projects. Never use leaked commercial code, ripped GTA models, proprietary textures or unlicensed assets. Keep reference clones outside the game import tree. Compare alternatives in a source audit: URL, pinned commit/version, license, files considered, performance, dependencies, adaptation plan and attribution. Run each candidate in isolation before selectively integrating. Preserve notices. Do not blindly copy whole projects or duplicate existing controllers. Write THIRD_PARTY_NOTICES.md and asset registry entries. No claim of compatibility before testing.

P23 | NPC BRAIN (PYTHON)
Implement seedable agent state with personality, needs, occupation, schedules, relationships, short/persistent memory, perception and action cooldowns. Use spatial indexing for hearing/vision candidates, utility scoring, contextual state machines and bounded goal planning. NPCs follow their own lives. Staring, following, bumping, familiar encounters, interrupted conversations, closing times, rain and dangerous driving produce natural varied responses. Some ignore, avoid or complain; no default player assistance. NPCs communicate with one another, queue, shop, cross, sit, work, use phones, seek shelter. No visible emotion bars or decision trees. Development-only logging is allowed. Python worker receives batched observations and returns validated action intents; Godot owns movement, collision, animation and actual world state. Local IPC only, timeout/restart, versioned schemas, no arbitrary eval. Distance-based updates and deterministic tests for memory, reaction diversity, path failures and conflicting goals. Persist meaningful encounters, not unbounded logs. Benchmark CPU per agent and avoid full-frame all-pairs scans.

P24 | TRAFFIC AND TRANSPORT
Build lane graph, vehicle following, intersections, signals, yielding, braking, turn indicators, parking, buses/taxi stops, rerouting and congestion behavior. Pedestrians wait and look before crossing; weather changes speed and stopping distance. Prevent deadlocks, clipping and spawning in view. Emergency vehicles can request priority in fictional simulation. Use pooled entities and lower distant update rates. Validate with fixed-seed stress scenarios, collision counts, queue length and actual FPS. Driver personality varies behavior without reckless randomness.

P25 | INTERACTIONS, PHONE, ECONOMY

No fake controls. HUD minimal, original and readable. Test keyboard/controller focus and closing menus restores control.

P30 | PERFORMANCE AND CODE HEALTH
Profile actual gameplay on identified hardware. Initial budgets: main character 40-70k triangles, nearby NPC 12-25k, distant 500-3000, hero car 30-60k, traffic 5-15k, small exterior 5-20k; adjust based on evidence. Compress textures, share materials, instancing, pooling, nav/physics budgets, LOD, culling, threaded loads, shader preparation. Low 720p/30fps and medium 1080p/60fps are targets only. Record median/p95/p99 frame times, RAM, VRAM, startup and streaming stalls. Test walking, fast driving, rain, night, crowded intersections, interiors, missions, saves and extended play. Audit duplicate logic, dead code, orphan assets, errors and regressions. Fix root causes not cosmetic overrides. Keep a benchmark report and truthful known limitations.

Headless tests cannot establish visual quality or GPU performance. Run interactive playtest, capture screenshots and benchmark before declaring a phase complete.
