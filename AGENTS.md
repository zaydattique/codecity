# BloomLogic | Engineering and production rules

## Product direction
BloomLogic is a native Python-first interactive 3D programming encyclopedia for Windows. Every lesson uses a distinct real-world exhibit, guided explanation, editable code, observable cause and effect, experimentation, and optional independent practice. No open-world game, missions, combat, driving, XP or compulsory quiz gates. No browser-only implementation or video presented as interactive geometry. The teacher character Dua is a fictional instructional representation, not a claim of likeness or authentic voice.

## Current baseline
Version 1.0.1 is merged and passed hosted Linux and Windows checks, including an offline packaged walkthrough and optional texture fault injection (run 45792172356). Physical Windows 10/11 compatibility still requires user validation. If / Else is the only interactive lesson; thirteen other exhibits are curriculum concepts. Read README.md, ROADMAP.md, ARCHITECTURE.md and the current evidence before every task. Do not expand until the current lesson's user-reported regressions are resolved.

## Engineering
Python 3.13 owns application navigation, curriculum, state, validated restricted CPython execution, simulation and orchestration. Panda3D 1.10.16 and panda3d-gltf 1.3.0 render real 3D assets. Blender 4.5 LTS authors editable assets; PyInstaller 6.16.0 packages Windows. Keep dependencies pinned. The internal package directory `codecity/` is a historical technical identifier, not the product name; do not rename it casually or introduce duplicate modules. No paid AI API or online runtime dependency. State is authoritative and deterministic. Use finite validated AST rules, bounded sensor domains, reproducible outcomes, atomic local persistence and useful errors. Never expose unrestricted Python execution as a secure sandbox.

## Learning and design
Each exhibit explains the concept, allows predictions, shows actual executed code and corresponding physical state, supports experimentation, and provides meaningful practice. Teach the boundary cases and failure outcomes. Use a coherent premium botanical design language, clear typography, meaningful controls, no emojis or eyebrow tags in the application. Do not use em dashes or generic AI copy in player-facing text. No fake progress, decorative controls or false completion. Preserve working UI, accessibility and offline behavior. The greenhouse is an illustrative compressed-time model, not species-calibrated biology or fluid physics.

## Art and licensing
Use professionally authored or original detailed geometry and licensed assets with source, revision, exact digest, attribution and license. Reuse existing verified assets when suitable. Avoid primitive humans and never present placeholders as finished. Keep editable Blender source and real runtime render evidence. Verify occlusion, character posture, roots, leaf geometry, water contact and camera composition. No photorealism claim based on prompts or test pass alone. Existing limits include discrete growth meshes, opaque glazing, synthetic narration and no facial lip synchronization. Keep CC0 provenance and dependency notices. Audit external licenses, avoid copying incompatible code, and check Git LFS quota before tracking selected binaries.

## Workflow and quality gates
Use focused branches and commits. Inspect existing files and AGENTS.md/CLAUDE.md before each phase; define goal, scope, affected files, risks and verification. Implement, test, inspect, fix regressions, then merge only verified changes. No destructive Git operations, secrets, caches, raw art libraries, Python environments or export archives in Git. Maintain README, AGENTS, CLAUDE, ROADMAP, ARCHITECTURE, HISTORY, ASSET_REGISTRY, FILEMAP, PERFORMANCE and THIRD_PARTY_NOTICES. HISTORY records actual changes in paragraphs; do not rewrite historical failures as successes.
Test core logic, real keyboard/mouse, actual rendered scenes, packaged Windows extraction, offline operation, pause/resume, invalid code, persistence, asset integrity and error paths. Texture maps require SHA-256 preflight and native filename conversion; missing optional maps degrade visibly/logged without blocking the lesson. Do not send malformed images into native codecs. Required assets remain strict. Test feature paths even if hosted hardware does not support them. Record OS, renderer, median/p95/p99 frame times, RAM and VRAM where measurable, load times and stutters. 720p/30 and 1080p/60 are targets, not promises. Hosted virtual GPU checks do not establish physical PC compatibility. Always disclose limitations and exact evidence.
